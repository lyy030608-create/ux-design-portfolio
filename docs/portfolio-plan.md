## 三个案例的不同叙事

Dose：商业利益难以识别 → 研究证据与标签比较 → 为什么采用 Paid Partnership → 分层流程（识别、理解、核查）→ V1 / V2 / V5 对比 → 客户反馈与边界。以 Screen showcase 与A1提取的真实界面作视觉主线；每个结论对应证据，不添加未经核对的百分比。封面用一张主手机界面与两个信息层面板，淡紫与暖白取自最终稿，不复制Nebula橙色。

Karaoke：公开选歌压力 → 评论研究、聚类、Persona → 私密预选机会 → 7版草图的决策 → 5个手表核心界面 → 手表与共享平板的交接 → 局限和反思。Hero以真实手表界面为主、平板为辅，紫色/洋红舞台氛围；不伪造新设备UI。流程用“推荐—预选—确认—共享队列”串联，最终以原稿核对。

Message Drift：校园参与障碍 → 匿名且可选的表达 → 真实纸板/Token原型 → 6人Think-Aloud发现 → 引导与自主选择的V2改进 → 实际交互原型 → 反思。Hero以海洋蓝数字界面与真实实体原型并置；AI装置概念图明确标注。原型优先iframe，并提供新标签打开；需后续验证实际路径与嵌入策略，不重造替代演示。

- Typography：第5–6页原创字形与字体海报合并为“字形到海报”的过程案例。
- Graphic Communication：第2–4页信息图、流程图和个人主题图表，按传播目的组合；不是默认所有作品都叫海报。
- Illustration & Icons：第8页图标系统及配色变体。独立手绘作品需高清材料确认。

## 视觉系统提案

以Enblox为首要参考，用户指定的渐变、紫色和编辑式排版优先于Taste Skill默认禁用规则。渐变集中在首页过渡/主视觉与Karaoke氛围，正文保持高对比纯色。

基础底色 #FAFAF7，正文 #171717；粉 #EB85BA、紫 #9066D8、橙 #F6A15A 为待视觉校准的全站强调色。Dose最终颜色从原稿提取；Message Drift使用深海蓝，不统一涂成紫色。

中文优先系统苹方/微软雅黑，英文先系统无衬线；开发阶段再评估可合法自托管字体，不依赖被阻断的字体CDN。桌面Hero 88–112px、手机44–56px；章节36–56px；正文17–18px、行高1.7；关键中文标题不能压缩到难读。

12列桌面/8列平板/4列手机；最大内容宽1320px，边距桌面48–64px/手机20px。间距基于8px序列，章节桌面96–144px/手机64–80px。左右外边距一致，变化放在内部栏宽、图文比例和视觉密度。

不复制参考的手持手机照片。项目截图从用户PDF提取，优先原始Figma导出；低分辨率区域不硬拉大。

## 交互与技术方案

建议 React + TypeScript + Vite，原生CSS变量构建设计系统；先不加入动画库。路由方案待托管决定：支持回退的托管使用标准路由；GitHub Pages需处理base与刷新回退，不能直接假定可用。

动效：内容轻量入场、项目图轻微缩放、标题/箭头反馈；不做滚动劫持。Case Study章节导航、返回顶部、移动菜单、图片弹窗均支持键盘与焦点恢复；prefers-reduced-motion禁用位移和持续动画。原型区域显示加载/失败提示和真实外链。

正式开发后以本地Vite + 浏览器做三尺寸验证；当前环境设置聊天未提供可分享预览链接，不能把localhost当作用户可打开的网址。Phase2需使用具备预览能力的开发任务或随后授权部署；本轮不发布。
